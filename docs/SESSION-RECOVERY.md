# 计时接续（1.4.2）

本功能从新版首次成功保存会话后生效。1.4.0 及更早版本没有会话快照，首次升级不能找回旧版从未保存的进度。

## 用户行为

| 重新启动时的情况 | 行为 |
| --- | --- |
| 同一工作时段，距离最后保存小于离开阈值 | 自动接续原坐站阶段、剩余时间及延后剩余时间 |
| 达到阈值、跨日、跨午休、跨工作时段、时钟回拨或日程设置变化 | 保留进度，等待“继续上次”或“重新开始” |
| 上次为手动暂停 | 保持暂停，不被“启动后开始计时”覆盖 |
| 上次已经在等待选择 | 继续等待，多次重启不会绕过确认 |
| 当前非工作时段 | 保留进度，“继续上次”暂不可用；工作时段恢复后可选择 |
| 没有有效历史会话 | 沿用“启动后开始计时”设置 |

离开阈值沿用“电脑离开与返回”设置，默认为 5 分钟，恰好达到阈值也需要确认。程序关闭期间不扣除倒计时或延后时间，不补计坐站统计、连续久坐和提醒响应时间。手动免打扰仍按原结束时间到期。

“重新开始”创建完整的久坐周期；在非工作时段操作会等待日程开放。恢复会话保留原阶段时长；若关闭期间更改了配置，继续上次仍使用原阶段时长，下一阶段使用当前设置。用户主动修改当前阶段时长则立即采用新值。

后台自启动遇到等待确认时显示一次托盘提示，不强制弹出主面板。主面板关闭仍只是隐藏；退出使用托盘菜单。已到点会话接续时遵守手动及全屏免打扰。

## 保存与异常

- 快照保存在 `%APPDATA%\LumbarReminder\session-state.json`，原子替换并保留 `.bak`。关键操作立即保存，运行期间每 15 秒保存，正常退出和系统关闭时再次保存。
- 正常运行且磁盘写入成功时，异常终止最多损失一个保存周期的进度；系统挂起或磁盘不可写时不能保证这一上限。
- 主文件损坏时尝试上一份快照，要求确认后继续。两份都不可读或格式不支持时保留文件、显示提示，并允许重新计时。后续新快照写入前将无效文件保存为 `.unreadable-<id>`。
- 更新请求保存失败时，旧进程继续运行，更新终止；用户可修复目录权限后重试。普通退出保存失败会询问是否仍使用上次进度退出。
- 更新候选在 WebView 就绪并超过启动存活检查前不能覆盖快照；安装版还需确认安装事务已提交且当前版本指向本进程，防止更新器繁忙或事务失败时过早写入。失败回退到支持相同会话格式的版本可恢复；回退到 1.4.0 或更早版本不保证接续。
- 真实提醒演示不会写入模拟的超时进度；桌宠动作试播与轻互动不重置计时。
- 会话不包含在 `.upyougo` 便携备份中。成功恢复个人数据时，同一事务移除旧会话并保留恢复前副本；恢复失败会回滚。

## 开发与验证

`SessionPersistence.cs` 提供带版本和字段校验的存储及可注入时间的恢复规则；`SessionRecoveryContext.cs` 将规则接入实际计时、提醒、统计与日程。当前格式版本为 1，记录阶段、模式、阶段时长、已用时间、延后剩余时间、UTC/本地时间、日程标识、免打扰结束时间和本阶段提醒记录标志。

运行 `qa/Test-SessionRecovery.ps1` 验证规则、文件异常与协调器；运行 `qa/Test-SessionProcess.ps1 -Package <本次ZIP>` 验证真实 WebView、跨进程恢复、强制终止、更新退出及启动失败回退。所有测试使用隔离数据，不操作用户正在运行的提醒进程。

商店候选编译相同会话模块，通过商店适配器保留自己的更新与自启动机制。商店分支的 `qa/Test-StoreSessionProcess.ps1` 验证未注册 MSIX 的真实进程重启；这不替代微软签名包的实际商店升级或 WACK。
