# 后续需求规划

以下是建议，不代表已实现或已承诺排期。当前基线见 REQUIREMENTS.md。

| 优先级 | 需求 | 价值与验收方向 |
| --- | --- | --- |
| P1 | 更新后接续计时 | 保存坐/站阶段、剩余时间、延后/暂停状态；更新和回退后可恢复，过期会话明确处理 |
| P1 | 数据导出与恢复 | 可导出个人设置和统计；恢复前校验并保留现有数据备份 |
| P1 | 安装维护完善 | 提供卸载入口、旧版本空间清理、安装目录迁移；默认保留个人数据 |
| P2 | 下载取消与恢复 | 用户可取消下载；弱网重试不打断当前计时，不留下无用临时文件 |
| P2 | 更新偏好与渠道 | 可关闭自动检查、忽略某次更新；维护程序本身的兼容升级协议 |
| P2 | 发布信任与运行兼容 | 可执行文件签名、更多 DPI/多显示器与 Windows 环境验证 |
| P2 | 核心规则进一步剥离 | 抽出不依赖 WinForms 的计时、日程与记录边界，为手机端复用规则 |
| 待验证 | 手机正式 App | 先验证后台提醒、通知权限和交互需求，再决定实现范围；不复刻桌面宠物窗口与安装器 |

先完成稳定分发和数据可恢复性，再扩大平台与功能。硬件联动目前维持历史工程，不纳入上述默认开发顺序。
